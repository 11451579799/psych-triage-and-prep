# 设计参考白名单与走查清单（Design References）

这份文件把 frontend-ui-architecture.md 第 9 节那条**原来只写在纸上**的「示例与参考来源政策」变成可执行的东西：给具体链接、说明每个链接解决什么问题、给出一条能照着做的走查清单。

## 一、为什么必须有白名单

精神科报告的读者处于两种极端状态之一：**症状急性期**（畏光、脑雾、手抖、读三行就累）或**就诊前的紧张**（只想要一句能复述的话）。生成式模型默认输出的「看起来像产品」的界面——高饱和渐变、玻璃拟态、无意义动效、暗底霓虹字——恰好是这两种状态下最难读的东西。把这类输出当参考，等于把错误示范固化成模板。

所以本仓库的规则是：**参考必须是人工创作、经真实用户验证的界面**，且每条参考要说明「它解决了什么具体问题」，而不是「它好看」。

## 二、白名单（每条标注：看什么 / 不抄什么）

| 参考来源 | 链接 | 看什么（具体到页面/组件） | 明确不抄什么 |
|---|---|---|---|
| **GOV.UK Design System** | https://design-system.service.gov.uk/ | 组件目录的「为什么这样设计」：notification banner（顶部状态条）、warning text（前置风险提示）、check answers（复诊要问的问题清单）、error summary（数据缺失如何诚实降级）。每个组件都有「何时使用 / 何时不用 / 可访问性」三段 | 它的视觉风格是给政务表单的，不抄配色，只抄「状态如何被无歧义地表达」 |
| **NHS Service Manual** | https://service-manual.nhs.uk/ | 「Design and delivery」下的设计指南：内容设计（content design）、可读性等级（reading age）、医疗信息的措辞规范 | 不抄英式医疗术语，只抄「把专业信息写到患者阅读水平」的方法论 |
| **Our World in Data** | https://ourworldindata.org/ | 长报告的信息架构：标题 → 一句话结论 → 图表 → 正文；以及 https://ourworldindata.org/grapher 的交互图表默认态（默认只显示能支撑结论的最少数据） | 不抄它的高密度数据页布局，我们一屏只该有一个结论 |
| **Distill.pub** | https://distill.pub/ | 交互式长文的阅读节奏：正文与可交互演示交替出现，每个演示都能独立读懂，即使不点也能看懂默认画面 | 不抄它的宽屏排版和大量留白；我们的报告要在手机 375px 上先成立 |
| **Linear** | https://linear.app/ | 暗色界面的对比度控制：**暗底不是黑底**，层级靠 surface 明度差而不是彩色高亮；字号与行高的克制 | 不抄它的工程工具隐喻，我们不是在管 issue |
| **Bearable** | https://bearable.app/ | 症状追踪的**低认知负荷录入**：一次一个维度、大点击区、可以只填一部分就保存 | 不抄它的打卡/统计视觉，我们不做长期追踪产品 |
| **Oura（Instrument 设计）** | https://ouraring.com/ | 「把生理指标翻译成一句人话」的做法：每个指标旁边都有一句解释它意味着什么、以及「这周的变化」 | 不抄它的消费级硬件美学和插画风格 |

**新增参考的唯一准入条件**：写清楚「它解决了什么具体问题」+「它的用户是谁、验证过吗」。写不出来的，不进白名单。

## 三、走查清单（生成报告后照着做一遍，不通过就改）

### A. 患者视角（急性期能用吗）

- [ ] **首屏 3 行读完**：断网打开，不滚动，只看第一屏，能说出「我现在该做什么」。做不到就是首屏失败。
- [ ] **放大测试**：手机上开最大字号（A+），所有卡片文字不溢出、表格可横向滚但页面不滚。
- [ ] **畏光测试**：把屏幕亮度调到最低，暗底是否仍可读；有无大面积高亮闪眼区域。
- [ ] **手抖测试**：用触屏单指，所有可点目标 ≥ 44px，两个相邻可点目标间距 ≥ 8px；没有需要精确拖拽才能完成的操作。
- [ ] **脑雾测试**：任意一个 section，只读标题 + 第一段，能不能知道这一节讲什么。术语首次出现必须有白话解释。
- [ ] **一句话可复述**：报告里有没有一句患者可以直接念给医生听的话（主诉 + 服药 + 目前的下一步）。

### B. 医生视角（30 秒）

- [ ] **30 秒定位**：能不能在 30 秒内找到 药名、剂量、风险等级、下一步建议 四项。
- [ ] **风险灯号**：红黄绿分层是否在顶部可见，不依赖滚动。
- [ ] **数据来源**：每个数字旁边有来源标注或「假设」字样；「未采集」不能写成「正常」。

### C. 环境（旧设备 / 离线 / 打印）

- [ ] **断网打开**：无 404、无字体回退错乱、无空白画布。
- [ ] **手机 375px 宽**：无横向滚动，图谱不重叠。
- [ ] **旧电脑**：无 backdrop-filter、无重动画；低配机器不掉帧。
- [ ] **打印 A4**：两页内，无内容裁切，风险色在黑白下仍可辨。
- [ ] **复制**：粘贴到记事本，中文与换行完整。

### D. 诚实性

- [ ] 报告里出现的每个药，都是用户说过的。
- [ ] 数据缺失时是明确标注缺失，而不是编一个看起来合理的数。
- [ ] 免责声明与危机热线在页脚可见（折叠也算，但折叠标题必须写清热线）。

## 四、反面清单（出现即重做）

- 深色背景 + 霓虹青紫渐变
- 大面积毛玻璃 / backdrop-filter
- 自动旋转的 3D 器官
- 双 Y 轴折线
- 8 条以上曲线同屏
- 满屏 emoji 当图标
- alert() 报错
- 把「未采集」写成「正常」
- 把 AI 生成的截图、配色方案、组件库当作设计依据
- 用「未来感 / 赛博 / 沉浸式」作为设计目标描述

## 五、评审只看四件事

不看炫技，只看：

1. 一个畏光、脑雾、手抖的人能不能读完第一屏。
2. 医生能不能在 30 秒内找到「药、剂量、风险、下一步」。
3. 断网、旧电脑、手机 375px 宽能不能用。
4. 数据缺失时有没有诚实降级，而不是编数。
